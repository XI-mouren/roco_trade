# roco-trade

游戏市场行情的众包采集与套利求解助手（NoneBot2 插件）。

> 游戏里的三个摊位每天随机给出不同货物的收购/出售价。
> 单个玩家只能看到自己服务器的行情，而这个插件把所有用户的截图汇总起来，
> 算出「在哪儿买、在哪儿卖」最赚，并且能跨服务器比较。

## 工作流程

```
玩家发截图  →  OCR 识别  →  版面还原成表格  →  入库  →  求解价差  →  推送最优路径
```

## OCR 版面还原

PaddleOCR 返回的是一堆带坐标的**离散文本块**，不是表格。这里做了三步还原：

1. **算中心点**：用文本框的左上与右下顶点求中心坐标 `avg_y` / `avg_x`
2. **行聚类**：按 `avg_y` 排序，相邻 40px 内归为同一行
3. **列排序**：行内按 `avg_x` 排序还原左右顺序；关键词过滤掉 UI 文案后，
   从行内正则提取价格

> 这套是面向固定界面的轻量规则方案。通用的做法是用 PP-Structure 之类的
> 表格结构识别（TSR）模型，本项目为了零额外依赖选择了规则实现。

## 数据模型

三张表，全部带 `UNIQUE` 约束并用 `ON CONFLICT DO UPDATE` 做幂等 Upsert：

| 表 | 内容 |
|---|---|
| `daily_price` | 谁、哪个服、哪个摊位、什么货、多少钱 |
| `daily_yield` | 每个货物的同服价差与跨服价差，以及买/卖的具体位置 |
| `historical_low` | 历史最大价差记录 |

存储用 `aiosqlite`，开启 WAL 模式。

## 两个设计细节

- **凌晨 4 点日切**：游戏在凌晨刷新行情，所以「今天」的边界不是 0 点而是 4 点
  （`day_boundary_hour = 4`）
- **30 秒录入窗口**：用 APScheduler 起一个定时任务，先攒够用户的多张截图再批量处理，
  避免每张图都单独跑一次 OCR

## 配置

在 NoneBot 配置中按需覆盖（均有默认值）：

```dotenv
db_path="roco_trade.db"        # SQLite 数据库路径
ocr_lang="ch"                  # OCR 语言
day_boundary_hour=4            # 日切边界小时
markets=["潮汐集市1号摊","潮汐集市2号摊","潮汐集市3号摊"]
```

OCR 模型默认从上级目录的 `modelfile/PaddleOCR` 加载（PP-OCRv6 medium det / rec）。

## 命令

| 命令 | 说明 |
|---|---|
| `/记录 角色名 摊位名` + 截图 | 录入单个摊位 |
| `/记录 角色名` + 3 张截图 | 一次性录入该角色的三个摊位 |
| `/我的市场` | 查看今日已录入数据，提示还缺哪些摊位 |
| `/查价` | 查看今日最优倒货方案 |
| `/历史低价` | 查看历史最大价差 |

## 已知限制

- 识别准确率依赖截图清晰度，压缩严重的截图需要用户重传
- 行聚类的 40px 是绝对像素阈值，靠 `det_limit_side_len` 统一缩放来缓解；
  不同分辨率下更稳妥的做法是改用相对高度
- 聚类参考点用的是「本行第一块」而非行内均值，界面轻微倾斜时会漂移
- 价格提取依赖关键词与行内最右侧数字，游戏 UI 改版会导致失效
- 跨服价差依赖多用户共同上传，单人使用时退化为同服价差
